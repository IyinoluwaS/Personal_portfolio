Syllo

Syllo turns a Canvas course export into one view of the semester (deadlines, exams, class meetings and course policies), so a student doesn’t have to open every page of every course. I was the backend lead and built the course import end to end.

01 — Problem

The semester is scattered across pages

Course information lives across syllabi, assignment pages and announcements, each written differently. Deadlines are buried in prose (“12 Oct 2027”), and missing one is costly.

Canvas can export a whole course as an EPUB file. Syllo reads that file and pulls out the parts a student actually plans around.

Who it’s for

College students who want a single, trustworthy list of what’s due and when, built from their own course material rather than a manual spreadsheet.

02 — Ownership

What I built, and what the team built

My work

  • The upload page and the review screen, where students edit, add or remove staged records before confirming
  • Staging tables, class meetings, source citations and the “Classes today” dashboard list
  • Tests for the import function: request handling, EPUB parsing, schema validation, classification and extraction

Team work

  • The React app shell and dashboard screens, generated with Lovable
  • Repository setup and hosting

03 — How it works

From an uploaded file to a confirmed semester

ModelDeterministic codeStudent

  1. Unpack safelyCodeChecks file size, entry count, compression ratio and paths before inflating anything.
  2. NormaliseCodeConverts each chapter to clean text, keeping headings, lists and tables, then splits it into sections.
  3. ExtractModelNemotron reads each section and returns records as JSON, with the source text they came from.
  4. ValidateCodeA strict schema checks types, dates and numbers. Records that don’t fit are rejected, not guessed at.
  5. ReviewStudentThe student edits, adds or removes staged records, with each record’s source shown alongside.
  6. ConfirmCodeOnly Confirm writes to the dashboard tables.

The model never sees the raw archive, only normalised text, and it can’t write to the database. Everything that decides what gets saved is deterministic code or the student.

04 — Decisions

Choices and their trade-offs

Review before commit

AI output is staged, not saved. The student sees every extracted deadline next to its source and confirms before anything reaches the dashboard.

Trade-off: one extra step for the student. In exchange, a misread date never lands silently in someone’s plan.

Parse deterministically, then use AI

Unpacking, cleaning and splitting the file is ordinary code with predictable behaviour and its own tests. The model only handles the part that needs judgement: reading prose and pulling out structured records.

Where the pipeline runs

The first backend I set up was FastAPI with SQLite. The pipeline that shipped runs as a TypeScript Supabase Edge Function, alongside the app’s existing Supabase database and sign-in.

05 — The hard part

An import that said “Complete” and saved almost nothing

Problem
A real Canvas export finished with a “Complete” status, but only the smallest section produced records. Large sections were being cut off by the model’s output limit, and their records were silently lost.
Fix
I raised the reply limit to 8,192 tokens and capped sections at 8,000 characters. I also made the function detect when a reply stops because of the length limit (finish_reason: "length") and re-read that section as two halves. If a half still can’t be read, the section fails visibly instead of quietly.
Result
Long sections now produce records, and a section that can’t be read shows up as a failure the student can see. Tests cover the truncation and re-read path. Along the way I also fixed a date bug: “12 Oct 2027” was being read as October 20.

06 — Security & reliability

Treating an uploaded file as untrusted

Archive safety

An EPUB is a ZIP file, so the importer checks limits before inflating anything: 30 MB per archive, 5,000 entries, 8 MB per entry, 48 MB inflated in total and a 200:1 compression-ratio cap to catch zip bombs. It rejects entry names that escape the archive (.. or absolute paths), duplicate names, ZIP64 and encrypted entries.

Validating model output

Every model reply has to match a strict schema. Invalid records are rejected rather than repaired by guesswork, and failures are reported instead of hidden.

Tests

Unit tests cover the request handler, EPUB parsing, schema validation, record classification and the truncation path, using synthetic EPUB fixtures. The early Python backend has its own tests for the data model and parser.

07 — Results

Where it stands

The import works end to end on a real Canvas course export: upload, extract, review and confirm, with the confirmed records feeding the dashboard and the “Classes today” list.

Known limitations

  • Schema checks prove a record is well formed, not that it’s correct. That’s why students review before confirming.
  • Extraction accuracy (precision, recall, invented dates) is planned in the project docs but hasn’t been measured yet
  • Only Canvas EPUB exports are supported; there’s no live Canvas integration

Next steps

  • Measure extraction accuracy on synthetic course fixtures, so changes can be compared with numbers
  • Build “Ask My Semester,” an assistant that answers only from imported material, with citations
